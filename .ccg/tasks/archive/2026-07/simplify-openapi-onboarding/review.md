# OpenAPI 接入简化建议

## 推荐交互

将现有 8 步向导拆为两个用户页面：

1. 导入：连接名称 + 上传/粘贴 OpenAPI（后续支持受控 HTTPS URL）。
2. 确认并启用：根据 `securitySchemes` 生成凭据表单；展示自动生成的只读/写工具摘要；只要求用户明确确认写操作，随后一键测试并激活。

## 系统自动完成

- Spec ID、修订号和格式识别。
- 导入、验证、发布、输入输出映射、默认策略、只读测试与激活的编排。
- 无 `x-mcp-tools` 时沿用后端现有能力，为每个 operation 自动生成单操作工具。
- 只读操作默认选中，写操作默认关闭；模糊操作按写操作处理。

## 高级模式

保留组合工具构建、自定义映射、逐项策略、修订管理、分阶段发布/激活和手动测试，但默认折叠为“高级设置”。

## 不可省略的安全边界

- 写操作必须显式同意，不能自动开启。
- 凭据动态表单提交后立即清空，后端加密且不可读回。
- 激活前必须通过后端验证和真实只读测试。
- URL 导入若实现，必须限制 HTTPS、私网/回环地址、DNS 重绑定、重定向、大小和超时，禁止远程 `$ref`。
- 全流程审计、幂等、失败回滚，不能产生半激活连接。

## API 建议

- `POST .../openapi/analyze`：只接收规范，返回不可变摘要、凭据字段、服务器候选和工具读写分类。
- `POST .../openapi/activate`：引用分析摘要，提交凭据和写操作确认，由后端串联现有导入/验证/发布/策略/测试/激活用例。

## 分期

1. 先做文件/粘贴的两页极速模式，隐藏组合工具构建器。
2. 增加受控 URL 导入、API Key/Bearer/Basic/OAuth2 客户端凭据表单。
3. 增加 Postman/cURL 导入和连接模板。

Gemini 因未配置 `GEMINI_API_KEY` 无法执行；Claude/GLM 分析进程在形成最终报告时异常退出，但其代码检查确认后端已能在未声明 `x-mcp-tools` 时自动为每个 operation 生成工具。
